Setting up your first Project
Simpler than it sounds, four steps to a working department manager.
1

Create the Project

Name it for the department or stream of work it covers, e.g. "Client Comms" or "Content."

2

Tell Claude what it's for, let it draft the instructions

Describe what this Project is for and what's going into it, and Claude can write the first draft of its own instructions for you to check over.

3

Point it at a folder

Whatever files this stream of work actually needs Claude to reference. This is usually wherever your files already live, a folder in Google Drive, Dropbox, or right on your own device. You don't need to move anything first. Inside the Project, use the paperclip or Add Context option and link straight to that folder.

4

Start working inside it

Memory builds itself from here, every conversation adds to what it knows. Every chat you have inside this Project stays listed there too, so you can scroll back and find a past conversation instead of losing it in your main chat history.

Stuck on step 2? Copy this into your new Project

Interview me about this Project so you can write clear instructions for it. Ask me what it's for, who it's for, and how I want output handled, one question at a time. Once you've got enough, draft the instructions based on my answers and show me for approval.

Better with every conversation
Outside a Project, every chat starts fresh except for your general instructions. Inside one, every conversation adds to what Claude already knows about that piece of your business. It gets more useful the more you use it, instead of starting from zero every time.
There's a practical bonus too. Files linked in as context are read directly, rather than pasted into every message. That uses far fewer tokens than copying the same document into chat again and again, so a Project is also a more efficient use of your usage limits.

Do this today: set one up. Give it instructions, point it at a folder, and watch what happens after a few real conversations.
