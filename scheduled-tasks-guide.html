Project or standalone?

There are two ways to set up a Scheduled Task. On its own (standalone), or inside a Project. The instructions work the same either way, what's different is how much the task actually knows when it runs.

⚙️

Standalone

Runs with only the instructions you gave it, nothing else. Fine for something simple and self-contained, checking one folder, pulling one report, the same steps every time.

🗂️

Inside a Project

Runs with the same instructions, plus that Project's own context, files and Memory behind it. Worth it the moment the task needs to make a judgement call, not just repeat a step.

💡
Why that difference actually matters
A Scheduled Task can't pause partway through and ask you a question. A weekly newsletter draft set up standalone can hit a decision it has no way to make, which voice to use, which client this update is actually about, and it has nowhere to turn. The same task set up inside a Project already has the brand voice, the client context and past decisions sitting there, so it can just make the call and keep going.

Simple version: nothing to judge, same steps every time, standalone is fine. Needs real context to make a call, build it inside a Project instead.
